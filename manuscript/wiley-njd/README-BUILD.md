## Template provenance

Downloaded 2026-11-06 from Wiley's author-services page
(https://authorservices-ppd.wiley.com/author-resources/Journal-Authors/Prepare/new-journal-design.html):
`WileyNJDv5_Template.zip` (8.8 MB, class + bibliography styles + fonts + sample),
plus the NJD journal spreadsheet `NJD-journals.xlsx`. Batteries & Supercaps is **not**
in the NJD title list; Wiley's page explicitly permits using the NJD template for
non-NJD journals, and this is the template the journal's own author-services route
points to.

Class options used: `\documentclass[AMA,Times2COL]{WileyNJDv5}` — AMA reference style
is the one whose output matches published Batteries & Supercaps references
(initials before surname, ≤ 6 authors then "et al.", journal abbreviated, year
bold, e-locator for 2022+), and Times is the closest serif to the journal's typeset
face.

## Three patches to the official class (each documented in-file)

1. **`\reserveinserts{28}` removed** — etex-pkg v2.7 exits before defining it on
   modern kernels (LaTeX ≥ 2015 allocates from the extended range itself). Without
   the patch the template dies on first compile. (`_patch_cls.py` history; pristine
   class preserved.)
2. **`\RequirePackage{bookmark}` commented out** — the bookmark package writes
   hex-escaped UTF-16 `\BKM@entry` lines into the `.aux` that do not round-trip on
   this kernel: every second compile died with *"File ended while scanning use of
   \BKM@entry"*. The only loss is the PDF outline; hyperlinks are unaffected.
3. The bundled old `listings.sty`/`natbib.sty`/etc. were quarantined into
   `_bundled-old/` because they shadowed TeX Live 2026 versions and caused a
   `listings` version mismatch; `mathastext.sty` needed a `tlmgr install`.

## Rebuild procedure

```powershell

cd wiley-njd

bibtex batt-main
pdflatex -interaction=nonstopmode batt-main.tex
pdflatex -interaction=nonstopmode batt-main.tex
python _layoutcheck.py           # layout + metadata + reference integrity (fails the build)
python _layoutcheck_selftest.py  # proves the guard still catches its four defects
python _verify_pdf.py            # element/wording checks, 42 refs, figure bbox
```

**Edit the markdown, never batt-main.tex** — the next `_md2tex.py` run overwrites it.

### The three build defects found on 2026-11-06 and how they are prevented

All three were **invisible to the old verifiers**: the PDF had every section and all 42
references while being unusable as a submission. Each now has a check in
`_layoutcheck.py`, and `_layoutcheck_selftest.py` injects each defect to prove the check
still fires.

| Defect | Symptom | Cause | Fix |
|---|---|---|---|
| **Blank page 1** | Page 1 held 16 words — running head + ORCID line only; the whole title block sat on page 2 | `\footnotetext{ORCID…}` placed **between `\corres` and `\abstract`, i.e. before `\maketitle`**. The class emits the footnote mark into the title strip and the strip is displaced. *Position is the trigger, and it was bisected, not guessed:* the same footnote **after** `\maketitle` is harmless (670 words on page 1). See `_bisect_blankpage.py`. | ORCIDs moved **into the `\corres` block**, which is part of the strip and cannot displace it |
| **Half-empty page 4** | One column of page 4 completely blank — half a page of white space in a paper at its word ceiling | The wide `table*` used `[!h]`, which LaTeX cannot honour for a double-column float, so it deferred the table and left the column empty | `table*[t]` |
| **Wrong affiliation superscripts** | Both authors printed superscript `1` although the affiliations are `1` and `2` | A stale `.aux` — text and metadata were right, only the rendered glyphs were wrong | Always build from a clean `.aux`; `_layoutcheck.py` check D asserts the rendered superscripts are `[1, 2]` |

### The reference-list defect (fourth)

Every entry in `references.bib` carried `note = {[M101] M1}` — an internal audit tag.
The AMA `.bst` prints `note` verbatim, so the **printed** reference list read
`… 2010;157:A196. [M120] M1doi: 10.1149/1.3268129`. The field is now **`audit_tag`**,
which `bst` ignores, so the tags stay in the `.bib` for the audit trail and out of the
PDF. `_layoutcheck.py` check E fails on any `[M106]`-shaped token in the output.
`wiley-njd/references.bib` must stay byte-identical to `04-literature/references.bib` —
`_assemble.py` copies it, so never edit the copy.

**`04-literature/references.bib.bak-notefield` is deliberate provenance, not a stale
backup.** It is the pre-fix `.bib` and contains the leak: **155 `note = {[Mnnn] Mn}` fields**
that the AMA style printed into the reference list. It is kept as the evidence for that
defect, so that the claim "the tags were there and leaked" can be checked instead of taken
on trust. In the **live** file the counts are `audit_tag` = 155 and `note` = 1 (one entry
carries a genuine, non-tag `note`); in the backup it is `note` = 156. Do not delete it, and
do not restore from it — restoring it reinstates the leak.

## Conversion notes (things that bit us)

- Run **bold before italic** in markdown conversion, or `**sources**` becomes
  `*\emph{sources}*`.
- Escape `%` **before** math replacements; a math string containing `\%` that goes
  through the global escape again becomes `\\%` — a LaTeX line break followed by a
  comment, which silently deleted the closing sentence of Loop B and its citation
  (bibliography dropped to 41/42 with no warning).
- `references.bib` was NFC-normalised (`Gunnarsdóttir` had a combining accent that
  pdflatex's utf8 inputenc rejects; the precomposed `ó` is fine).
- The figure is vector, so it embeds as a Form XObject — `get_images()` cannot see
  it; `_verify_pdf.py` checks the page content bbox instead (506 × 460 pt on page 3,
  aspect 1.10 = 17.8/16.2).

## The diagnostic scripts in this folder, and which to keep

Nothing here is part of the build. They are the audit trail for the defects above, and each
one is the evidence behind a claim in the table — so they are kept deliberately. If you are
cleaning up, these are **not** scratch:

| Script | What it is for | Keep? |
|---|---|---|
| `_layoutcheck.py` | **The regression guard.** 14 checks: title page not blank, no empty column, title block on one page, affiliation superscripts, no leaked audit codes, reference count/contiguity, citation order, Figure 1 / Table 1 / References present. Exits 1 on any defect. **Run on every build.** | **keep — load-bearing** |
| `_layoutcheck_selftest.py` | Proves the guard still fires: injects the blank-page, audit-leak and missing-reference defects and asserts the guard FAILS each time, then restores and byte-compares. Wrapped in `try/finally` (an earlier version without it corrupted `references.bib`). **Run after changing the guard.** | **keep — load-bearing** |
| `_verify_pdf.py` | Element/wording checks (section 6 phrasing, data-availability ending, both ORCIDs, no AI/CRediT sections) + reference count + figure bbox. | keep |
| `_bisect_blankpage.py` | The experiment that established the blank page was caused by the **position** of `\footnotetext` (before `\maketitle`), not its presence. Reads `_b_cur.tex`. | keep — it is the evidence |
| `_b_cur.tex` | Verbatim copy of the pre-fix `batt-main.tex`, i.e. the known-bad input for the bisect above. **Not** a stale build of the current file; do not delete it thinking it is an old artifact, and do not rebuild from it. | keep — bisect input |
| `_fillcheck.py` | Per-page column-fill reporter that first located the empty column on page 4. | keep — provenance |
| `_tryfloats.py` | Float-placement bisect that established `table*[t]` as the fix for the empty column. | keep — provenance |
| `_bisect.py` | Generic variant bisect from the same investigation. | provenance only |

Lesson recorded here because it cost the most time: **two of the three defects were invisible
to every pre-existing verifier.** `_verify_pdf.py`, `_conformance.py`, `_sync_check.py` and
`check_checklist.py` all passed a PDF with a blank first page and a blank column, because
they check *content* and the content was all present. Page-level geometry needs a page-level
check. And a guard that only ever prints PASS proves nothing — every check in
`_layoutcheck.py` is falsification-tested by `_layoutcheck_selftest.py` for exactly that reason.
